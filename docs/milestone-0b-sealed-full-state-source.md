# ForgeProof 0B — Complete application-state inventory and sealed export

**Status:** Experimental source-only capability. **Not** connected to any published application, production PostgreSQL database, hosted private Git ledger, or billing/identity provider. This module does not authorize a migration or production release.

The separate ForgeProof application has ten reviewed PostgreSQL application tables: users, sessions, repositories, attestation_receipts, api_keys, organizations, org_members, subscriptions, pending_emails, and audit_logs. The reviewed fixed column list includes all available fields, including potentially sensitive tokens, session JSONB, private evidence, queued email content, account state, and subscription references. No row or secret is silently discarded. Stripe-managed provider synchronization and webhook tables are **outside this application snapshot** and require separate continuity checks.

## Two opt-in library operations

- `inspectCompleteApplicationSource` checks all ten tables within one injected, read-only, repeatable-read PostgreSQL transaction, using reviewed expected counts, strict fixed columns, and an externally provided HMAC key. It returns **counts and keyed commitments only**, never plaintext rows or unkeyed identity fingerprints.
- `captureSealedFullState` independently captures all ten tables from one injected transaction. It strictly checks the reviewed source schema, missing or extra columns, row identities, expected counts, SQL null semantics and safe JSON types. Each complete table (including empty tables) is encrypted under a separate random nonce with AES-256-GCM. Authenticated associated data binds the version, table, scoped tenant/repository, keyed source commitment, schema and counts. An independent HMAC-SHA256 key commits to the normalized source contents deterministically across repeated exports. The output contains ciphertext, authenticated metadata, counts and commitments—not plaintext SQL rows, customer IDs, access tokens, original source fingerprint or database credentials.
- `openSealedFullState` accepts only the sealed envelope, reviewed manifest, exact tenant/repository scope and **both** separately provisioned 32-byte keys. It rejects malformed ciphertext, noncanonical base64, wrong scope/keys/counts/schema, repeated nonce, source-order discrepancies and damaged identity integrity. The plaintext it returns is sensitive and must remain in the caller's separately authorized, protected runtime. Never send the decoded rows through chat, logs, GitHub source, public telemetry or an external agent tool.

The canonicalized JSON represents a validated SQL export, not the original PostgreSQL on-disk byte encoding or historical HTTP issuance payload. Existing Ed25519 receipt signature / predecessor verification is separate; the sealed exporter alone does not verify commercial truth or migrate records into Git's authoritative application state.

**Source-identity binding:** The externally reviewed `sourceDbFingerprint` may itself reveal a private database hostname or infrastructure label. Its raw value is therefore deliberately **not** persisted in the sealed envelope. Instead, the exporter stores `HMAC-SHA256(hmacKey, sourceDbFingerprint)` and binds that authenticated commitment into every per-table AES-GCM AAD. On open, the supplied reviewed manifest and HMAC key must regenerate exactly the same commitment, or decryption is rejected before any plaintext can be returned. A synthetic negative test explicitly changes the source fingerprint and verifies rejection, while confirming the raw fingerprint never appears in the envelope. Do not weaken that confidentiality guarantee by publishing the original fingerprint.
