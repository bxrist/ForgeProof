# Owner-operated isolated restore capture

Source-only implementation; productionGoAllowed is always false. No application route imports these modules. This is not Darwin acceptance or authorization to cut over production.

`captureIsolatedRestore` in `server/git-store/isolated-restore-capture.mjs` accepts an object with an exclusive, idle, authenticated injected pg `client`, `trustedPreflight(client)`, `privateKeySource()`, externally reviewed `manifest`, and `{tenantId, repositoryId}` scope. No CLI, automatic connection, environment key loading, key creation or Keychain access is provided.

The actual operator must manually invoke this library in a separately authorized private owner runtime. Protected archive access was restricted; Codex must not open it. Use separately owned custody for two independent, nonzero 32-byte keys, supplied in memory by the private injected source as `{encryptionKey, hmacKey}`. Keep backups and recovery custody separate from the ciphertext. The adapter copies and clears its working key buffers; the owner retains responsibility for caller buffers, pg memory, process isolation, swap/core dumps and private logging configuration. Never log query results or injected exceptions.

The trusted callback must independently verify OS UNIX peer identity, authentication, server process ownership, socket isolation, and absence of TCP listeners for this exact connected backend. Return `{authenticated:true, transport:'unix', peerIdentityVerified:true, noTcpListeners:true, backendPid, databaseUser}`. Merely returning these booleans without OS verification is not a preflight implementation. The adapter cross-checks backend PID/user against SQL and requires the exact database forgeproof_0b_restore_test, PostgreSQL 17, empty listen_addresses, and no TCP client address. The operator must freeze writers, DDL and restore jobs throughout capture and save. A privileged or malicious database server is outside this boundary.

Only public application tables with the existing fixed column inventory are accepted. Additional schemas (including temporary schemas), tables visible through information_schema, or columns reject capture. Do not adjust the existing inventory semantics to force compatibility. Unexpected compatibility requires stopping and separately reviewing the mismatch. Catalog visibility must be complete for the supplied owner role.

The exact required counts, in existing table order, are 3 users, 12 sessions, 9 repositories, 17 receipts, 2 API keys, 1 organization, 1 membership, 2 subscriptions, 0 pending emails and 15 audit logs: 62 rows. The existing captureSealedFullState owns each repeatable-read read-only transaction. The adapter authenticates the first envelope in memory, verifies its receipt head, repeats source preflight and capture, and compares deterministic keyed whole-state commitments. It rejects count drift and content drift even with unchanged counts. It returns only the first encrypted envelope, counts, keyed commitment and productionGoAllowed:false. A change followed by reversion between snapshots cannot be detected; exclusive operational quiescence is required. No cross-process claim of perpetual immutability is made.

Optional persistence: call `saveIsolatedEnvelope(directory, filename, envelope, {scope, encryptionKey, hmacKey, manifest})` with an existing owner-owned 0700 directory outside every Git tree. The saver authenticates the envelope before serialization; only ciphertext and authenticated envelope metadata are written. Names are restricted to simple .json basenames. All directory ancestors are checked for symlinks, untrusted owners/writers and .git markers. Sticky system temporary ancestors are allowed; use a dedicated owner account and a stable private directory for actual custody. Same-UID hostile processes are outside this filesystem boundary. The filesystem must support no-follow opens, hardlinks and directory fsync. Unsupported operations reject; do not weaken checks for platform convenience.

A fresh exclusive 0600 temporary file receives encrypted JSON, file fsync and exact descriptor readback. An atomic hardlink publishes without overwriting existing files, symlinks or hardlinks. Temporary unlink and directory fsync complete success. Failures attempt cleanup and return only a bounded error. After interruption, crash or cleanup failure, the owner must privately reconcile any surviving encrypted file before retrying; failure is never proof that no artifact exists. No plaintext SQL, tokens, Git commits or publication are produced.
