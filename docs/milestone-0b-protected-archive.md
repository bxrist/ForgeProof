# Milestone 0B — protected historical evidence archive preflight (source-only)

The `buildProtectedHistoricalArchivePreflight(source, encryptionKey)` function is an opt-in nonproduction, in-memory staging helper. It does not access ForgeProof's live PostgreSQL database, create an export file, access Stripe, modify authentication, push Git history, or change the default production server. All historical data supplied to it must come from a separately authorized, independently reviewed and consistent SQL snapshot. The original owner directions remain authoritative; this engineering method is not an additional policy.

## Input and evidence

The caller provides source version 2, a private tenant and repository identifier, complete receipt and audit rows with **raw UTF-8 serialized export bytes**, and an independently reviewed manifest: expected receipt/audit record counts, historical head entry hash, trusted original public signer keys and source database fingerprint. A separate 32-byte runtime encryption key is required. No key, plaintext source row or secret is returned in the staged output. A trusted upstream application must also prove that the supplied keys, manifest and source extraction actually correspond to the production database. The function cannot do that from self-asserted input.

Before emitting **any** migration stage, all receipts are checked against the *existing* legacy Ed25519 signature verifier, exact expected source-column names, original receipt IDs, pinned public signer keys and the complete global predecessor hash chain ordered by numeric receipt ID. Both non-null and null historical audit metadata are retained; audit logs have no original individual Ed25519 signatures, so their integrity requires independent source export proof and the newly signed private Git event. Duplicate IDs, unknown columns, omitted columns, mismatched totals, conflicting signers, modified signed fields, wrong predecessor/head and invalid source buffers fail closed.

The resulting `stagedMigration` contains only sealed private Git records with AES-256-GCM ciphertext and redacted validation cores, stable idempotency keys and an integrity digest. Existing Git `migrate` preflight performs its own canonical event signing and checks before publication. The *same exact staged ciphertext* must be reused across retries; rebuilding with a new random nonce would create a logically different request. This helper does not publish its output or guarantee transactional migration across an entire multi-event archive.

## Genuine provenance and confidentiality limits

Original receipt Ed25519 signatures do not authenticate every historical field, including metadata, audit details or file path. The new protected private Git event signature commits to the full encrypted envelope and its redacted core; it cannot retroactively authenticate a human/AI author or precise model/geographic origin. A clone without a decryption key can validate the signed historical hash chain and ciphertext digest, but cannot recover private metadata. Complete authorized recovery needs the separately protected runtime key and must return the exact **serialized export input bytes**. If original issuance-response bytes were never stored in SQL, this function does not reconstruct or pretend to recover those original response bytes.

Use an isolated private Git evidence store with actual OS/provider ACLs and independently protected checkpoint/trust pins. **Never commit private staged transactions, ciphertext containing protected customer data, original source snapshots or encryption keys to the public ForgeProof source repository.** Even encrypted records require retention, rotation, ACLs, recovery and privacy review. Runtime encryption keys and original SQL records are not written to logs.

## Not a finished 0B cutover

This archive covers historical evidence only, not users, credentials, active sessions, repositories, organizations, subscriptions, commercial billing/provider state, or business continuity. Its in-memory builder does not offer a consistent PostgreSQL transaction/snapshot. The available Replit native read-only production callback could return scalar aggregates, but does not support transaction-control statements or independent secure export; its production-read-replica aggregates therefore cannot serve as the final authoritative snapshot.

Before closing 0B, independently prove the complete 17-receipt historical original/global chain, complete existing application state, secure credential and session custody/reauthentication, encrypted private git write/read/restore on real provisioned infrastructure, commercial/Stripe continuity and rollback, released ForgeProof version, separately integrated LifeOS consumer and Darwin acceptance. Synthetic green tests are necessary but not evidence of production recovery. Maintain ForgeProof/LifeOS project separation.
